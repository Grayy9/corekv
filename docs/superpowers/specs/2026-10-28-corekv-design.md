# CoreKV 设计

## 目的

构建一个可解释、可测试的 C++20 单机嵌入式 KV 引擎，作为 GameEdge 的存储方向互补作品。重点是持久化顺序、崩溃恢复、不可变有序文件与压实，不追求与 RocksDB/LevelDB 的吞吐竞争。

## 交付边界

- 公共 API：`Open(directory)`、`Put(key,value)`、`Get(key)`、`Delete(key)`、`Flush()`、`Compact()`。键与值为二进制字符串；空键拒绝。
- 单进程、单写者。通过目录锁防止同一目录多进程同时打开。API 调用由互斥锁串行化。
- 每次写入先追加 WAL 并同步到磁盘，然后更新 MemTable。默认保证已返回写入在进程崩溃后可恢复；硬件及文件系统断电保证取决于平台。
- MemTable 达到配置字节阈值时同步刷盘。SST 先写临时文件、同步、原子重命名，再清空 WAL。启动时扫描已完成的 SST，按编号顺序装载，再重放 WAL。
- WAL 尾部不完整记录可截断恢复；完整记录的校验失败应报告损坏。SST 校验失败也应报错，不能静默跳过。
- 手动压实将所有 SST 的最新键状态合并到新 SST，保留删除标记；新文件发布后才删除旧文件。中断后新旧文件共存时，新文件编号更大，读取仍以最新文件为准。
- 有命令行演示工具、自动化测试、基本压测脚本和 README。先在 Windows 本地验证，CI 使用 Linux 与 Windows。

## 实现取舍

- SST 首版将键与文件偏移建立内存索引，值仍从文件读取；这是易于验证的教学实现，索引内存开销为 O(键数)。
- 不实现事务、并发写入、范围扫描、压缩、布隆过滤器、复制或分布式协议。
- 压测报告只记录当前环境与吞吐，不宣称优于成熟引擎。
